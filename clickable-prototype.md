## Reflection

**What usability issues can a clickable prototype reveal that a static wireframe cannot?**

        Static layouts cannot show how a user experiences pacing, transitions, or structural dead ends. A clickable prototype reveals if a modal window traps the user, if navigation feels disorienting, or if an interactive target is too small to tap easily. For example, in a static wireframe, a dropdown menu might look fine, but when you click it in a prototype, you might realize it covers important content or is hard to use on mobile. A prototype allows us to test the flow and interaction before investing in development, catching issues that only become apparent when users can actually click through the design.

**How can prototyping help designers communicate ideas more clearly to developers?**

        Handing over an interactive prototype eliminates the need for long, text-heavy functional documents. Developers can experience the exact flows, hover states, and animations firsthand, leaving zero room for guesswork during coding. For instance, instead of describing a complex interaction in words, a designer can simply show it in the prototype. This leads to fewer misunderstandings and a smoother development process. It also allows developers to ask specific questions about the design, as they can see exactly how it’s supposed to work rather than interpreting static images or written descriptions.

**What are common mistakes designers make when creating prototypes?**

        Designers often slow down the user experience by adding overly flashy, slow animations instead of keeping transitions snappy. They also tend to build rigid happy paths that break if a tester misclicks, or fail to label layers properly, which ruins automated transitions. Another common mistake is not testing the prototype with real users, leading to a design that looks good in theory but doesn’t work well in practice. Additionally, some designers might focus too much on making the prototype look perfect rather than ensuring it effectively communicates the intended user experience. It’s important to strike a balance between visual fidelity and functional clarity when creating prototypes.
