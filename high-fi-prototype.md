## Reflection

**How can a high-fidelity prototype help developers build the final product accurately?**

        A high-fidelity prototype provides developers with a flawless visual specification. Instead of guessing spacing or padding, they can inspect the exact CSS properties, export precise asset files directly from Figma, and see the exact behavior of micro-interactions, reducing code revisions later. For example, if a button has a specific hover state or animation, developers can see it in the prototype and implement it exactly, rather than trying to interpret a static design. This leads to a more accurate final product that matches the designer’s vision and reduces the need for back-and-forth clarification during development.

**What are the risks of focusing too much on visuals before usability is validated?**

        Focusing on beautiful UI elements too early can mask catastrophic usability flaws. A stunning interface might trick stakeholders into approving a layout that is actually confusing to navigate, leading to expensive structural re-work later when users get stuck on basic tasks. For instance, if we design a visually appealing dashboard without testing the user flow, we might find out after development that users can’t find key features or get lost in the navigation. It’s crucial to validate usability with low-fidelity prototypes before investing time in high-fidelity visuals to ensure we’re building something that not only looks good but also works well for users.

**How can small details like button states, hover effects, and transitions improve the user experience?**

        Small details like distinct hover states, loading animations, and subtle page transitions remove user anxiety. They provide instant visual feedback, confirming that the system has registered a click or action, which makes the entire digital experience feel polished and trustworthy. For example, a button that changes color when hovered over gives users confidence that it’s interactive. Loading animations can reassure users that the system is working on their request, reducing frustration during wait times. Transitions between pages can make navigation feel smoother and more intuitive, guiding users through the flow of the application. These details contribute to a more engaging and satisfying user experience, making the product feel more responsive and well-crafted.
